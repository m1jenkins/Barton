## Repeatable capture template

Copy this metadata block for a future extraction and replace every `unavailable` with an observed value or leave it explicitly missing:

```text
capture_id: unavailable
extracted_at_utc: unavailable
extraction_method: authenticated_browser | supported_API | sanitized_owner_export
source_property: unavailable
source_timezone: unavailable
source_reporting_identity: unavailable
window_start: unavailable
window_end: unavailable
last_complete_date: unavailable
reporting_lag_or_freshness: unavailable
search_type: web
filters: unavailable
aggregation: property | page
rows_returned: unavailable
source_row_limit_and_pagination: unavailable
anonymization_thresholding_or_sampling: unavailable
completeness: unavailable
campaign_price_content_annotations: unavailable
restricted_evidence_reference: unavailable
```

1. Read the existing property; select the latest mutually comparable 28 **completed** days, excluding preliminary data. Record GA4's timezone and lag before aligning dates. If timezones differ, label the difference rather than joining daily figures as though they match.
2. In GSC, obtain a dimensionless property aggregate separately, then dates, query, page, country, and device breakdowns. Obtain joint query/page/device/country data only if actually needed and available; mark its completeness separately. Up to 16 months means the history the property actually exposes.
3. If using the supported Search Analytics API, use read-only scope, `type: web`, `dataState: final`, explicit dates, and pagination. Google's API still does not guarantee every possible row. [API specification](https://developers.google.com/webmaster-tools/v1/searchanalytics/query)
4. For query segmentation, save the versioned brand expression and a separate ambiguous-brand bucket. Preserve an unassigned remainder. Never label unreported queries non-brand by subtraction.
5. For GA4, capture session default channel group/source/medium, landing page, device/country, sessions/users, and the approved events. Record reporting identity, filters, consent/modeling, thresholding, and currency. Keep `Organic Search` separate from referral/AI/campaign cohorts.
6. Reconcile deduplicated ledger leads and verified paid sessions to outbox deliveries and destination acknowledgements through durable IDs in restricted storage. Commit only aggregate counts, status, and discrepancies. Do not equate Google clicks to GA sessions or try to join individual search queries to customers.
7. Annotate the actual offer activation and page release dates. Compare a stable pre-existing-page cohort separately from new releases. Reassess the first three guides and worksheet only after their actual eligibility/release changes.

Suggested sanitized export columns:

```csv
capture_id,source,property,timezone,start_date,end_date,dimension,dimension_value,clicks,impressions,ctr,position,aggregation,complete,notes
```

Keep raw exports in access-controlled evidence storage. A UI `—`/`~`, missing row, unavailable field, or suppressed result must not become a fabricated zero during export handling.

## Event-to-business-metric definitions and reconciliation sheet

| Event / metric | Valid counting basis | Do not count as this metric |
| --- | --- | --- |
| `cta_click` | Intent interaction under the existing contract | Lead or purchase |
| `phone_click` | Phone-link interaction | Connected call or qualified inquiry |
| `generate_lead` | Successful durable receipt with lead ID; deduplicate by durable ID | Raw DOM form submission or API failure |
| Qualified inquiry | Deduplicated contactable prospective buyer, in-scope vehicle request, and actual buying intent documented in authorized records | Every form, phone click, or unknown-quality lead |
| `begin_checkout` | Durable checkout attempt created; separate abandoned/restarted attempts | Paid order |
| `purchase` | Server-verified paid Checkout Session, durable purchase/session ID, recorded amount/currency | Confirmation view, refresh, client-supplied amount, failed/unpaid session |
| `onboarding_complete` | Durable onboarding completion attached to a verified order | Merely opening an onboarding page |
| Organic purchase/revenue | Verified purchase with allowed organic attribution and a declared first/last-touch rule | GA4 attribution silently substituted for ledger semantics |
